# 架构总览

## 一句话

把「写爆款网文」从**个人手艺**变成**可复制的工业流水线**：7 层 9 人，层层交付，每章 5 关。

## 信息流

```
                    ┌──────────────────────────────┐
                    │   🎯 操盘手 (闻风口)          │
                    │  只调度 · 只看板 · 只验收      │
                    └──────────────┬───────────────┘
                                   │  所有跨角色信息流经此中转
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
   ┌─────────┐              ┌─────────────┐            ┌─────────────┐
   │ 研究层   │              │ 规划层       │            │ 创作/质检层   │
   ├─────────┤              ├─────────────┤            ├─────────────┤
   │ 探骊(扫榜)│──选题报告──▶│ 构骨(架构)   │──大纲人设─▶│ 开锋(黄金三章)│
   │ 千面(拆解)│──模板包────▶│ 节律(细纲)   │──逐章细纲─▶│ 快刀(正文)    │
   └─────────┘              └─────────────┘            │ 化凡(去AI)    │
                                                        │ 铁尺(三维质检)│
                                                        │ 数瞳(数据)    │
                                                        └──────┬──────┘
                                                               │
                                                        ▶ 交付 / 数据反馈
```

**串行约束**：化凡（去 AI）**必须**在铁尺（质检）之前；铁尺 REJECT 后按问题归属退回对应角色。

## 分层设计原则

| 原则 | 说明 |
|:---|:---|
| 单一职责 | 每层只解决一类问题，上一层产出是下层原料 |
| 硬指标前置 | 每阶段有量化验收线（对话比/密度/评分），不达标即退回 |
| 执行决策分离 | 操盘手不产出内容，只做编排与验收 |
| 事实源唯一 | `story-state.json` 是所有角色共享的状态快照，避免各自为政 |
| 机械化优先 | 能用脚本卡的标准（结构/节奏/连续性/字数）一律脚本化 |

## 九角色速览

| 代号 | 定位 | 关键产出 | 关键硬指标 |
|:---|:---|:---|:---|
| 探骊 | 扫榜军师 | 选题报告 | 赛道竞争指数、对标数据 |
| 千面 | 爆款拆解师 | 写作模板包 | 对话比 / 句长 / 段落节奏统计 |
| 构骨 | 故事架构师 | 大纲 + 人设 + 世界观 | 主线句、起承转合比例 |
| 节律 | 章节规划师 | 逐章细纲 | 场景节拍 ≥10/章、情绪曲线 |
| 开锋 | 开篇包装师 | 书名 + 简介 + 黄金三章 | 前 300 字三件套 |
| 快刀 | 正文写手 | 章节正文 | 对话比、字数 2000–2500/章 |
| 化凡 | 去 AI 专员 | 去 AI 稿件 + 报告 | AI 味 10 维度总分 |
| 铁尺 | 三维度质检 | 审核报告 + 裁决 | 编辑 / 读者 / 一致性 |
| 数瞳 | 数据分析师 | 数据诊断 | 完读率、追更比 |
