# 番茄爆款创作团 · Tomato Novel Studio

> 一套面向**中文网络小说（番茄小说平台）**的工业化创作流水线：**7 层、9 个专业角色**，由一名「操盘手」统一调度，用 Agent 编排把写小说变成一条有质检、有硬指标、可规模化的生产线。

<p align="center">
  <b>扫榜研究 → 故事架构 → 章节规划 → 开篇包装 → 正文创作 → 去 AI 化 → 三维质检 → 数据调优</b>
</p>

## 这套东西解决什么问题

写网文最大的痛点是**不稳定**：今天写得爽，明天写崩；开篇能爆，后劲不足；AI 写出来一股「机器味」，读者三章就弃。

本项目把「爆款」拆成**可复制的工序**：

- **每章至少过 5 道关**才允许发布（研究 → 架构 → 细纲 → 开篇/正文 → 去 AI → 质检）。
- **硬指标前置**：对话比 ≥40%、每 500 字一个恐怖锚点 / 爽点、章末必留钩子、AI 味 10 维度评分……不达标**就地退回重跑**，不靠「写完再改」。
- **执行与决策分离**：操盘手**绝不亲自写稿**——只调度、只验收。团队产出不对，就修规则重跑，而不是自己上手动稿。
- **角色说话指纹**：让读者遮住名字就知道是谁在说话（口头禅 / 反应模式 / 用词习惯 / 句式节奏 四维模型）。
- **机械化校验**：把「凭感觉」变成「凭脚本」——结构、节奏、连续性三类检测脚本。

## 快速开始

这不是一个「装了就能跑」的软件，而是一套 **Agent 编排协议 + 知识库 + 脚本**。用法：

1. **读 [SKILL.md](SKILL.md)** —— 这是编排协议（谁在什么阶段干什么、怎么互传）。
2. **把角色定义喂给你的 Agent** —— 每个子任务加载 `references/0X-*.md` 作为 system prompt。
3. **按 SOP 串联** —— 参考 [docs/工作流.md](docs/工作流.md)。
4. **用脚本卡硬指标** —— `scripts/ss-check.py` 等把质检数据化。

> 本仓库在 [Hermes Agent](https://hermes-agent.nousresearch.com/docs) 上用 `delegate_task` 实现角色编排；任何支持「子任务 + 角色 system prompt」的框架（Claude Code、自定义编排器）都能跑。

```bash
git clone https://github.com/<你>/tomato-novel-studio.git
cd tomato-novel-studio

# 结构/节奏检测
python3 scripts/ss-check.py --file examples/正文.txt --full

# 状态管理
python3 scripts/story-state.py --init --title "书名" --genre "悬疑恐怖"
```

## 核心方法论（节选）

- **冲突前置**：开篇前 300 字完成对立 / 秘密，拒绝背景陈述型、无冲突进行时、设定介绍型开场。
- **认知落差**：爆款开篇五花八门，底层都是「读者以为 A，结果发现是 B」的落差。
- **恐怖来自日常科技失效**：手机没信号 / 无人机图传断 / GPS 负海拔 / 充电宝同时没电——不是鬼怪和环境渲染。
- **禁止写法**（违反一条重写）：状态陈述式（「水是红的」）、「XX 说」对话标签、环境渲染恐怖、神秘台词开头、分析推理型对话。
- **虐爽节奏**：禁止憋屈超过 2 章——虐完必须立刻爽，不隔夜。
- **字数必脚本验证**：任何字数声明必须脚本核实，不信手动标注。

完整规则见 [`knowledge/01-写作铁律145条.md`](knowledge/01-写作铁律145条.md)。

## 适配范围

- ✅ 中文网络小说（番茄小说等中文平台），现实题材 / 悬疑恐怖 / 复仇爽文 / 言情等主流赛道。
- ✅ 短故事（3 万字 / 10 章）与长篇连载。
- ⚠️ 世界观设定如西幻 / 科幻可复用流水线框架，但部分知识库条目面向「都市/现实/悬疑」赛道，需自行替换赛道数据。
